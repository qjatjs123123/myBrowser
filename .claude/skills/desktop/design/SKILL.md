# 화면 디자인 — myBrowser 기준

이 앱은 **브라우저**다. 사용자의 주 관심은 탭 안의 웹페이지이고, 우리가 그리는 UI(상단 크롬·사이드바)는 그것을 방해하지 않아야 한다.

## 0. 우선순위 (충돌 시 위가 이긴다)
1. **앱 디자인 토큰** — `src/renderer/styles/globals.css` 의 shadcn 변수(`--background`, `--primary`, `--muted` …). 색 하드코딩 금지.
2. **shadcn/ui 부품** — `@/components/ui/*`. 없는 부품은 `pnpm dlx shadcn@latest add <부품>`.
3. 이 문서의 원칙.

## 1. 레이아웃
```
┌──────────────────────────────────────────────┬──────────────────┐
│ [탭][탭][+]                                   │  에이전트 사이드바   │
│ ◀ ▶ ⟳  [주소창                    ]  [≡]       │  (기본 360px,      │
├──────────────────────────────────────────────┤   접을 수 있음)     │
│                                              │  ┌ 작업 입력 ─────┐ │
│          WebContentsView (웹페이지)            │  │ 오늘 7시 2명 … │ │
│                                              │  └───────────────┘ │
│                                              │  단계 타임라인       │
│                                              │   ● 페이지 열기 ✓   │
│                                              │   ● 날짜 선택 ✓     │
│                                              │   ◉ 승인 대기 …     │
│                                              │  [중단]            │
└──────────────────────────────────────────────┴──────────────────┘
```
- 상단 크롬 높이는 탭 줄 36px + 주소창 줄 40px. 사이드바는 오른쪽, 토글 가능, 폭은 전역 store 에 저장.
- 탭 영역의 크기는 main 이 `WebContentsView.setBounds` 로 맞춘다 — renderer 는 자기 레이아웃만 그리고 크기 변화를 IPC 로 알린다.

## 2. 크롬(상단바) 원칙
- **중립·저대비**: 배경 `bg-background`, 경계 `border-border`, 아이콘 `text-muted-foreground`. 강조색은 쓰지 않는다 (페이지 콘텐츠와 경쟁 금지).
- 주소창은 `Input` 기반, 포커스 시만 `ring`. 로딩은 주소창 왼쪽 작은 스피너, 진행 막대 금지.
- 탭은 활성만 `bg-background`, 나머지 `bg-muted`. 닫기 버튼은 hover 시 노출. 파비콘 16px.
- 키보드: Ctrl+T/W/L/Tab 은 main 의 메뉴 단축키로 처리하고 renderer 는 표시만.

## 3. 사이드바 원칙 — 상태가 먼저 보인다
- 맨 위에 **현재 상태 배지** 하나: `대기` / `실행 중` / `승인 필요` / `질문` / `완료` / `실패`. `승인 필요`·`질문` 은 `bg-primary` 로 유일하게 강조.
- **단계 타임라인**: 한 줄 = 도구 호출 하나. 아이콘(도구 종류) + 사람 말로 된 요약("예약 페이지 열기", "날짜 11월 7일 선택") + 결과 상태. 원문 JSON 은 접힌 상세에.
- 에이전트의 **생각**(thinking 요약)은 작은 회색 글씨로 접어서. 기본 접힘.
- 스크린샷 썸네일은 타임라인 옆 64px, 클릭하면 확대.
- 작업 입력은 하단 고정 `Textarea` + 실행 버튼. 실행 중엔 입력을 잠그고 **중단** 버튼을 같은 자리에.

## 4. 승인·질문 모달 — 놓치면 안 되는 결정
- `AlertDialog`(shadcn). 제목 "승인 필요" / "질문". 본문은 **에이전트가 하려는 행동 한 문장 + 대상(버튼 문구·URL)** 을 그대로 보여준다.
- 버튼은 두 개뿐: `승인`(primary) / `거부`. 기본 포커스는 **거부**. Enter 로 승인되지 않게 한다.
- 질문 모달은 선택지 버튼(있으면) + 자유 입력.
- 모달이 떠 있는 동안 타임라인은 `승인 대기` 로 표시하고, 탭 위에는 반투명 테두리(에이전트가 가리키는 요소를 하이라이트)를 둔다.

## 5. 공통
- 문구는 한국어, 짧게. 버튼은 동사("승인", "거부", "중단", "실행").
- 로딩/에러/빈 상태를 모두 처리한다 — 타임라인이 비었으면 "할 일을 입력하면 여기에 진행 상황이 표시됩니다".
- 아이콘은 lucide-react 만. 클릭 영역 최소 32×32(데스크톱 앱 기준).
- 다크 모드는 OS 설정을 따른다(`prefers-color-scheme`), 토큰으로만 대응.
- 애니메이션은 150ms 이내, 상태 전환(배지·타임라인 추가)에만.
